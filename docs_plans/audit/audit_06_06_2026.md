## 3. Проверка схемы данных (п. 3 check_rule.md)

### 3.1. Ошибки (11 шт.)

| Код | Проблема | Где |
|-----|----------|-----|
| DB-E1 | Перечислимые типы без CHECK / ENUM (`source_type`, `document_type`, `era`, `status` и др.) | `db_diagrams.md` |
| DB-E2 | Хэш-поля как `text` вместо `CHAR(64)` | `db_diagrams.md` |
| DB-E3 | `chat.sessions.document_ids` — массив `bigint[]`, нарушение 1НФ | `db_diagrams.md` |
| DB-E4 | Отсутствие UNIQUE-ограничений для 6 бизнес-ключей | `db_diagrams.md` |
| DB-E5 | Отсутствие ON DELETE / ON UPDATE для всех FK | `db_diagrams.md` |
| DB-E6 | `chat.sessions.user_id` — phantom FK (таблица `auth.users` отсутствует) | `db_diagrams.md` |
| DB-E7 | Отсутствие индексов для часто запрашиваемых полей | `db_diagrams.md` |
| DB-E8 | Противоречие: `updated_at` в ER-диаграмме vs отсутствие в `db_audit_report.md` | `db_diagrams.md`, `db_audit_report.md` |
| DB-E9 | Отсутствие soft-delete (`deleted_at`) | `db_diagrams.md` |
| DB-E10 | Отсутствие таблицы `users` при наличии FK | `db_diagrams.md` |
| DB-E11 | `document_sections.content` — JSONB без GIN-индекса (противоречие в документации) | `db_diagrams.md`, `db_audit_report.md` |

### 3.2. Предупреждения (16 шт.)

- `float` для `confidence` — избыточен (`real` достаточно).
- Отсутствие DEFAULT у счётчиков (`chunk_count`, `message_count`).
- `document_sections.content` — JSONB без схемы.
- `document_snapshot` — неограниченный JSONB (риск мегабайтных строк).
- `format_code` + `format_label` — частичная функциональная зависимость.
- Нет составного индекса для диапазонных запросов по дате.
- Нет CHECK на положительность счётчиков.
- Денормализация `document_chunks.document_id` (риск рассинхронизации).
- `chat.sessions.message_count` без механизма синхронизации.
- `chat.messages.sources` — JSONB вместо таблицы.
- Несогласованность именования timestamp-полей (`uploaded_at`/`event_at`).
- Несогласованность полей «кто изменил» (`created_by`/`uploaded_by`/`changed_by`).
- Несогласованность полей «статус» (`validity_status`/`processing_status`/`current_status`/`status`).
- Разные стили FK-наименования (`source_document_id` vs `successor_doc_id` vs `resolved_document_id`).
- `document_versions.updated_at` — противоречие между ER и аудитом.
- Таблица `pipeline.drafts` не отражена в ER-диаграмме.

### 3.3. Предложения (9 шт.)

- Lookup-таблицы для `issuing_body` и `group`.
- Единый справочник `document_type` + `source_type`.
- Частичные индексы для FSM-фильтров.
- Партиционирование для высоконагруженных таблиц.
- HNSW вместо IVFFlat на старте.
- COVERING-индексы.
- Таблица `terminology` (есть в JSON, нет в БД).
- Подтвердить тип `date` для `adoption_date` / `effective_from`.
- Задокументировать семантику `replaces` + `predecessor_doc_id`.
