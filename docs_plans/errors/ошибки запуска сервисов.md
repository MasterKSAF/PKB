1. Auth Service (порт 8082) — нет `email-validator`

**Текст ошибки:**

```
ImportError: email-validator is not installed, run `pip install 'pydantic[email]'`
```

**Где падает:**

```
auth_service/app/main.py:4  →  from app.api.v1 import audit, auth, internal, roles, users
  →  app/api/v1/audit.py:10  →  from app.schemas.schemas import AuditListResponse
    →  app/schemas/schemas.py:32  →  class UserCreate(BaseModel):
      →  поле с EmailStr → pydantic требует email-validator
```

**Причина:** в `auth_service/app/schemas/schemas.py` модель `UserCreate` (и, вероятно, другие) использует `EmailStr` из pydantic. Эта аннотация требует установки пакета `email-validator` (`pip install pydantic[email]`), которого нет в `backend/requirements.txt`.

**Исправление:** добавить в `backend/requirements.txt`:

```
email-validator>=2.0.0
```

Или установить прямо: `pip install pydantic[email]`

После этого перезапустить контейнер:

```bash
docker compose -f backend/service_checker/docker/docker-compose.yml restart app
```

### 2. Gateway Mock (порт 8081) — ошибка импорта `router`

**Текст ошибки:**

```
ImportError: cannot import name 'router' from 'mocks.auth_service.main' 
(/app/backend/gateway_service/mocks/auth_service/main.py)
```

**Где падает:**

```
gateway_service/mocks/gateway.py:33
  from mocks.auth_service.main import router as auth_router
```

**Причина:** файл `gateway_service/mocks/gateway.py` на строке 33 делает импорт:

```python
from mocks.auth_service.main import router as auth_router
```

Но в файле `gateway_service/mocks/auth_service/main.py` нет переменной/объекта `router`. Там скорее всего есть `app` (FastAPI-приложение) или что-то другое. Нужно смотреть, что экспортируется из этого модуля.

**Возможные исправления (на усмотрение разработчика):**

- Добавить `router` в `mocks/auth_service/main.py` (если там есть роутер)
- Или изменить импорт в `gateway.py` — импортировать `app` вместо `router` и использовать `app.router`
- Или переписать `gateway.py`, чтобы не зависеть от внутренностей auth-мока

**Как проверить, что экспортируется:**

```bash
docker compose -f backend/service_checker/docker/docker-compose.yml exec -T app grep -n "^router\|^app\|^from\|^def\|^class" /app/backend/gateway_service/mocks/auth_service/main.py
```

### 3. Registry Service (порт 8084) — нет модуля `env`

**Текст ошибки:**

```
ModuleNotFoundError: No module named 'env'
```

**Где падает:**

```
registry_service/main.py:17
  import env
```

**Причина:** в `registry_service/main.py` на строке 17 есть `import env`, но файл `registry_service/env.py` не существует. Вероятно, это должен быть файл с настройками окружения (переменные, конфигурация).

**Что нужно сделать (на усмотрение разработчика):**

- Создать `registry_service/env.py` с нужными переменными
- Или удалить `import env` и переписать конфигурацию через pydantic-settings (как сделано в других сервисах — `orchestrator_service/app/core/config.py`, `rag_search_service/app/core/config.py` и т.д.)

**Пример минимального `env.py`, который решит ошибку:**

```python
# registry_service/env.py
# TODO: заменить на pydantic-settings
import os

DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///./registry.db")
SECRET_KEY = os.getenv("SECRET_KEY", "change-me")
```

Но лучше сразу переписать на pydantic-settings по единому шаблону проекта.
