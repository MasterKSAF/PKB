# RAG — эксперименты по настройке поиска (Фаза 2)

Подбор оптимальной конфигурации индексации и поиска для RAG на нормативной документации ПКБ. Оценка на эталонной базе из 44 вопросов, на документном уровне, со статистической проверкой значимости (Wilcoxon + поправка Holm-Bonferroni) и сводным скором по формуле §9 методики.

## Финальная конфигурация

| Параметр | Значение |
|---|---|
| Модель эмбеддингов | Qwen3-Embedding-4B (int8, dim 2048, без промпта) |
| Чанкование | fixed_1024 (1024 символа), overlap 10% |
| Стратегия поиска | Vector + Rerank |
| Реранкер | bge-reranker-v2-m3 (мультиязычный) |
| top_k | 10 |

## Ключевые выводы

- Чанкование: чанки 1024 символа дают Hit@5 = Recall@5 = 1.0 при меньшем числе фрагментов (3745 против 7493 у 512 символов).
- Модель: Qwen3-4B статистически неотличима от 8B (p = 0.59), но вдвое легче по VRAM; режим без промпта лучше instruct.
- Поиск: качество определяет наличие реранкера (+6-9% MRR), а не способ слияния. Мультиквери непригодна.
