# Аномалии / уточнения (зафиксированные по ходу работы)

## 05.06.2026 — Уточнение моделей эмбеддингов (беседа Игорь — Полина)

1. **Модели Qwen — переименование.** В исходной методике (§2.2) были указаны `Qwen2.5-4B` / `Qwen2.5-8B`. Это генеративные модели, а не эмбеддеры. По факту используются `Qwen3-Embedding-4B` / `Qwen3-Embedding-8B`. Исправлено.

2. **Размерность 8B.** Было 3584 (от Qwen2.5-8B), стало 4096 (от Qwen3-Embedding-8B). Для 4B размерность 2560 осталась верной.

3. **MRL (Matryoshka) — только Qwen3.** Усечение размерности поддерживается только Qwen3-Embedding. У e5-large, bge-m3, MiniLM размерность фиксированная. Соответственно, перебор по мерности идёт только для Qwen3.

4. **Сетка размерностей:**
   - 4B: 2560 / 2048 / 1536 (макс 2560)
   - 8B: 4096 / 2048 / 1536 (макс 4096)
   - Цель: проверить, оправдана ли размерность >2000 для индекса в БД.

5. **Квантование int8.** Для продакшена цель — int8-квантование. Стандартный sentence-transformers не держит int8 корректно (грузит как FP16). Нужен bitsandbytes или Infinity-сервер. VRAM: 4B int8 ~4 ГБ, 8B int8 ~8 ГБ.

6. **Переиспользование индекса.** Индекс строится 1 раз на связку (chunk + overlap + model + dim) и переиспользуется всеми стратегиями поиска. Но эмбеддинги запроса считаются на каждый ран (embed, rerank, bm25, multiquery). Псевдокод утилиты обновлён с учётом кеширования.

7. **Таймлайн.** 2 недели: 1-я неделя — пробный прогон, 2-я — итоги. Команда делится на 2 подгруппы: одна готовит тестовый проект, вторая — сценарий (документы/вопросы/ответы).
