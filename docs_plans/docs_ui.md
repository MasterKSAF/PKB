# Часть 1. Окно «База знаний»

Окно отображает реестр зарегистрированных документов, разделы базы знаний и операции просмотра/управления карточкой.

## 1. Карточки состояния

Под верхней панелью отображаются четыре карточки:

- **Документов в реестре**
- **OCR завершён**
- **Индексировано**
- **Требуют внимания**

Карточки считаются по списку документов, который загружается из:

`GET /documents`

## 2. Раздел «База знаний по разделам»

В блоке отображаются карточки разделов базы знаний.

Каждая карточка содержит:

- название раздела;
- описание раздела;
- количество документов в разделе.

Данные загружаются через:

`GET /classifiers/tree`

При нажатии на карточку раздел выделяется в интерфейсе.

## 3. Таблица документов

Колонки таблицы:

- **Документ**
- **Тип**
- **Версия**
- **Источник**
- **OCR статус**
- **Индекс статус**
- **Обновлён**
- меню действий через три точки

Список документов загружается через:

`GET /documents`

Для каждого документа интерфейс использует поля:

- `document_id` или `id`;
- `title`, `filename` или `name`;
- `document_type`, `source_type` или `type`;
- `latest_version` или `version`;
- `source` или `uploaded_by`;
- `status` (отражает FSM Пайплайна 1/2: `created`, `pending_index`, `indexing`, `indexed`, `failed`);
- `updated_at` или `created_at`.

## 4. Действия по документу

У каждого документа есть меню через три точки.

### Открыть предпросмотр

Открывает модальное окно предпросмотра документа.

Используется запрос:

`GET /documents/{document_id}/file`

В окне отображаются:

- название документа;
- ID документа;
- тип;
- версия;
- OCR статус;
- индекс статус;
- ссылка на файл, если она вернулась от Gateway;
- карточка документа.

### Скачать документ

Сначала интерфейс получает данные файла через:

`GET /documents/{document_id}/file`

Если в ответе есть `file_url`, интерфейс пытается скачать файл по этой ссылке.

### Изменить метаданные

Открывает модальное окно редактирования метаданных.

Поля:

- название документа;
- тип;
- версия;
- источник.

После сохранения изменения отображаются в интерфейсе.

### История версий

Открывает модальное окно истории версий.

Используется запрос:

`GET /documents/{document_id}/versions`

В окне отображаются:

- номер версии;
- ID версии;
- название;
- статус;
- дата создания;
- размер файла, если он есть.

### Назначить раздел

Открывает модальное окно выбора раздела базы знаний (список из `GET /classifiers/tree`).

После выбора раздел отображается под названием документа в таблице.

### Архивировать

Открывает окно подтверждения архивирования.

Используется запрос:

`DELETE /documents/{document_id}`

После подтверждения документ скрывается из таблицы.

## 5. Уведомления (просмотр)

Всплывающие уведомления показывают результат действий просмотра/управления:

- документ скачивается;
- метаданные обновлены;
- раздел назначен;
- документ архивирован;
- действие не принято серверной частью.

# Часть 2. Окно «Загрузка документов»

Окно отвечает за пре-стейдж загрузки и Пайплайн 1 (Формирование документа) — черновик → preview → решение → full → Registry, а также за повторный запуск пайплайна для уже загруженных документов.

> Черновик (`draft`) — **обязательная точка входа.** Без черновика загрузить документ невозможно (см. `docs/pipelines/pipeline1-formation.md:6`).

## 1. Верхняя панель действий

- **Загрузить документ**
- **Загрузить по ссылке**
- **Повторить OCR**

### Загрузить документ

Кнопка открывает выбор файла на компьютере пользователя.

После выбора файла в интерфейсе отображается сообщение:

> Выбран файл: [название файла]. В рабочем режиме он будет отправлен в хранилище, OCR и индекс.

В рабочем режиме интерфейс инициирует Пайплайн 1:

1. `POST /drafts` — создание черновика и загрузка файла в MinIO (заголовок `Idempotency-Key`, ответ `202 {draft_id, task_id}`).
2. `POST /drafts/{draft_id}/preview` — запуск preview-фазы (OCR/Parser preview + Converter-validator preview + check-uniqueness).
3. `GET /drafts/{draft_id}/preview/status?longpoll=15` — ожидание `ready_for_approve`.
4. `PATCH /drafts/{draft_id}/decide?action=approve|reject` — решение пользователя. После `approve` запускается full-фаза и запись в Registry.

### Загрузить по ссылке

Кнопка отображает уведомление о загрузке документа по ссылке. В рабочем режиме URL также формирует черновик через `POST /drafts` (вариант с источником-ссылкой), далее — тот же сценарий preview → decide.

### Повторить OCR

Кнопка запускает повторную обработку OCR для выбранного документа.

Используется запрос:

`POST /documents/{document_id}/reprocess`

(возвращает `202`, документ снова проходит OCR/Parser → Converter-validator → Registry → Индексация).

## 2. Действия загрузки в меню документа

Из меню «три точки» в таблице базы знаний доступно действие, относящееся к загрузке:

### Перезапустить OCR

Запускает повторную обработку выбранного документа.

Используется запрос:

`POST /documents/{document_id}/reprocess`

## 3. Окно предпросмотра черновика (preview / decision point)

Модальное окно decision point после завершения preview-фазы (статус черновика `ready_for_approve`). Отображает:

- первичные метаданные (`doc_code`, `title`, `document_type`, `year`, `revision`);
- список кандидатов-дубликатов (из `check-uniqueness`);
- кнопки **Approve** / **Reject** (`PATCH /drafts/{draft_id}/decide`).

## 4. Уведомления (загрузка)

Всплывающие уведомления показывают результат шагов Пайплайна 1:

- выбран файл;
- файл отправлен в обработку (черновик создан);
- preview завершён;
- OCR/индексация запущены;
- найден дубликат / черновик отклонён;
- ошибка распознавания (`PREVIEW_TIMEOUT`, `DECISION_TIMEOUT`, `INDEX_TRIGGER_TIMEOUT`);
- действие не принято серверной частью.
