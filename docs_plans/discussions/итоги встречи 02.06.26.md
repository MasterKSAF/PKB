## Итоги совещания (группа разработки пайплайна обработки документов)

### 1. Основные решения

| Решение                                                        | Описание                                                                                                                                                                                                                                                                |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Предпросмотр (preview) сохраняется**                         | Endpoint превью нужен не для отображения пользователю, а для ранней классификации документа (проверка уникальности, определение типа). Оставляем в сервисе парсинга, даже без кнопок действий – данные используются другими сервисами (конвертер, валидатор, registry). |
| **Первая версия сервиса парсинга – на Open Data Loader**       | Диана продолжает доработку текущей реализации (обёртка, валидация, нормализация, JSON на выходе). Сервис должен быть рабочим (пусть с косяками) для первичного тестирования пайплайна.                                                                                  |
| **Вторая версия – на базе Lama Parser (облачный OCR/парсинг)** | Дмитрий интегрирует Lama Parser, который показывает отличное качество распознавания (таблицы, формулы, повёрнутые страницы, сложные макеты). Возможно объединение парсинга и OCR в одном сервисе.                                                                       |
| **Вопрос безопасности Lama Parser остаётся открытым**          | Lama Parser – облачное решение. Для открытых данных подходит, но для конфиденциальных документов может быть недопустим. Альтернатива – локальные библиотеки с LLM (например, Marker PDF), но нужны мощности (GPU).                                                      |
| **Схема обработки**                                            | Все документы сначала идут через парсер. Для скан-копий парсер вырезает страницы как картинки, OCR обрабатывает каждую картинку и заменяет её текстом в итоговом JSON.                                                                                                  |
| **Форматы документов**                                         | Пока фокус только на PDF. Поддержку `.doc`, `.docx` и других добавим позже, если успеем. Конвертация всех форматов в PDF – как дополнительный «плюс», но не обязательный.                                                                                               |
| **Проверка безопасности и типов**                              | Остаётся внутри сервиса парсинга (у Дианы – ручная валидация, у Lama Parser – встроенная).                                                                                                                                                                              |

### 3. Договорённости и уточнения

- **Две версии сервиса парсинга будут существовать параллельно** (локальная на Open Data Loader и новая на Lama Parser).  
  - Если новая версия покажет стабильную работу и закроет вопросы безопасности – локальную заархивируем.  
  - Если нет – локальная останется резервной (API-совместимой).
- **Предпросмотр не требует действий от пользователя** – он нужен только внутренним сервисам (конвертеру, валидатору, registry). Диана поправит endpoint превью, чтобы он работал корректно.
- **Сравнение инструментов** – необходимо прогнать одни и те же сложные документы через Open Data Loader, Marker PDF и Lama Parser. Результаты сравнения обсудить на следующем совещании.
- **Документация** – Диана вышлет в Telegram диаграмму пайплайна, а также ссылки на GitHub с описанием сервиса. Запись встречи будет выложена для всех.
- **Принятые решения фиксируются письменно** – на будущее протоколировать основные моменты (как сделано сейчас).

### 4. Открытые вопросы (требуют дальнейшего обсуждения)

- **Безопасность** – допустимо ли использовать облачный Lama Parser для документов с грифом «конфиденциально»? Нужно уточнить у заказчика.
- **Ветвления в пайплайне** – что делать, если валидация не пройдена или документ не уникален? Пока идём по прямой схеме (загрузка → обработка), логику ветвлений будем прорабатывать в оркестраторе позже.
- **Обработка цветных таблиц** – Lama Parser пока не распознаёт данные, переданные цветом. Требуется дополнительная настройка схем.
