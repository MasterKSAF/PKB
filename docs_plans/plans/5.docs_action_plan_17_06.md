### 5. Вывод: три главные проблемы

1. **Документация отстаёт от обсуждений на 1–2 недели.** Решения 08.06 и 16.06 (два бакета, Infinity, SigNoz, единый /process) есть в протоколах, но не внесены в docs/. Разрыв будет только расти, если не выделить время на синхронизацию.

2. **65 вопросов UI-команды — индикатор пробела.** Наличие 65 открытых вопросов к backend означает, что API-документация не является достаточной для разработки клиента. Особенно критичны Q36 (формат классификации), Q20 (промежуточные метаданные) и Q58-65 (permissions).

3. **JSON-схемы — второй источник истины, расходящийся с первым.** schema_parser_result.json, schema_converter_result.json и schema_registry_for_rag.json содержат устаревшие поля (`group`), неверный нейминг (`okstu`, `udc`) и не включают поля, описанные в API (`quality`, `validation`, `llm_usage`). Разработчики, которые начнут реализацию по JSON-схемам, получат неполный API.
