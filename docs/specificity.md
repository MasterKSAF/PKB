### 🟡 A2. bbox: пиксели в raw_ocr_v4, нормированные в validated_v3 (в работе)

- `schema_parser_result.json` (raw_ocr_v4): bbox в пикселях — `[10.0, 10.0, 100.0, 18.0]`, страница 210×297 px (`page.width`, `page.height`).
- `schema_converter_result.json` (validated_v3): bbox нормированные — `[0.05, 0.028, 0.5, 0.05]`.
- `glossary.md`: определение bbox — «0..1».

**Решение (уточнено 04.06)**: Parser/OCR возвращают **raw bbox (px) + размер страницы**. Converter-Validator **нормирует bbox → [0,1]** (делением на `page.width`/`page.height`). Parser и OCR НЕ делают нормирование — это лишняя работа, дублирующая логику конвертера.
**Статус**: в работе, дедлайн 10.06.

### 🟢 A3. Версия raw_ocr: план говорит v2, документация — v4 (решено)

- Сводный план: `raw_ocr_v2` — единый контракт.
- `schema_parser_result.json`: `"schema": "raw_ocr_v4"`.
- API OCR и Parser: ссылаются на `raw_ocr_v4`.

**Решение**: финальная версия контракта — **`raw_ocr_v4`**. Все упоминания `raw_ocr_v2` в сводном плане заменены на `raw_ocr_v4`.

### 🟡 A7. Отсутствие сущности «проект» в чатах (решается в Спринте 1)

- **Проблема**: Gateway и QueryService не поддерживают сущность «проект» (судостроительный заказ). Чаты не сгруппированы по проектам, фильтры истории не позволяют отобрать чаты по проекту.
- **Решение**: ввести таблицу `chat.projects` (id, code, name, status) и поле `project_id` в `chat.sessions`. API QueryService обновить: `project_id` в создании/редактировании сессии, фильтр `project_id` в списке сессий и истории.
- **Статус**: добавлено в план Спринта 1 (04.06), реализация — до 10.06.
