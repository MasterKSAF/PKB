# Нормализатор: алгоритмы дедупликации и бизнес-ключ

> Описание алгоритмов нормализации названий документов, вычисления бизнес-ключа и извлечения кодов классификации.

---

## 1. Назначение

Нормализатор — компонент Converter-validator (и опционально Registry), который:

1. **Вычисляет бизнес-ключ** (`title_hash_sha256`) для дедупликации документов
2. **Нормализует названия** — приводит к единому виду, устраняет разночтения (GOST → ГОСТ, латинские аватары, римские цифры)
3. **Извлекает коды классификации** (МКС/ОКС, ОКСТУ, УДК) из текста первых страниц
4. **Определяет эру и юрисдикцию** документа по году и типу источника
5. **Строит JSONB `classification_status`** — статус извлечения каждого кода

---

## 2. Бизнес-ключ (title_hash_sha256)

### 2.1. Формула

```
title_hash_sha256 = SHA-256(era | source_type | mks_oks_code | okstu_code | doc_code | normalized_title)
```

Где:
- `era` — эпоха: `USSR`, `CIS`, `RF`, `CURRENT`
- `source_type` — тип источника: `gost`, `gost_r`, `ost`, `rd`, `tu`, `iso`, `dnv`, `astm` (нижний регистр)
- `mks_oks_code` — код МКС/ОКС (или пустая строка, если NULL)
- `okstu_code` — код ОКСТУ (или пустая строка, если NULL)
- `doc_code` — регистрационный номер документа (напр. `20868-81`, `2.105-95`)
- `normalized_title` — нормализованное название (результат алгоритма раздела 3)

**Разделитель**: `|` (pipe). Если поле отсутствует (NULL), в ключ не включается.

### 2.2. Примеры

**ГОСТ СССР 20868-81:**
```
USSR|gost|47.020||20868-81|стойки...
→ SHA-256 → a1b2c3d4...
```

**ГОСТ Р 2.105-95:**
```
RF|gost_r||okstu_code|2.105-95|ескд...
→ SHA-256 → e5f6g7h8...
```

**DNV-RU-SHIP-Pt3:**
```
CURRENT|dnv|47.020||dnv-ru-ship-pt3|rules for classification...
→ SHA-256 → i9j0k1l2...
```

### 2.3. Почему бизнес-ключ, а не ID файла

| Подход | Проблема |
|--------|----------|
| По имени файла | Один ГОСТ в PDF и DOCX — две разных записи |
| По хэшу файла | Один ГОСТ в PDF (скан) и PDF (цифра) — две записи |
| **Бизнес-ключ** | **Один ГОСТ → одна запись, независимо от формата и количества файлов** |

## 3. Нормализация названия

### 3.1. Общий алгоритм

```
Вход: сырое название документа (raw_title)
Выход: normalized_title + is_foreign + needs_review

1. Приведение к нижнему регистру
2. Замена буквы 'ё' на 'е'
3. Если is_foreign = True → упрощённая нормализация:
   - Удаление всех разделителей (пробелы, дефисы, точки, скобки)
   - Вычисление бизнес-ключа, выход
4. Токенизация по разделителям [пробел, дефис, точка, скобки]
5. Для каждого токена:
   a. Сверка с терминологическим реестром (terminology_registry)
   b. Если не найден → проверка на римские цифры
   c. Если не римские → детект смешанных скриптов (латиница+кириллица)
   d. Если смешанные → замена латинских аватаров на кириллицу
6. Сборка и вычисление бизнес-ключа
```

### 3.2. Сверка с терминологическим реестром

Таблица `registry.terminology` содержит эталонные написания. Нормализатор ищет токен в `raw_term` и заменяет на `normalized_value`.

Пример кэша:
| raw_term | standard_term | normalized_value |
|----------|---------------|------------------|
| gost | ГОСТ | гост |
| ГОСТ | ГОСТ | гост |
| gost r | ГОСТ Р | гост р |
| ГОСТ Р | ГОСТ Р | гост р |
| iso | ISO | iso |
| dnv | DNV | dnv |
| astm | ASTM | astm |
| ost | ОСТ | ост |
| rd | РД | рд |
| tu | ТУ | ту |

### 3.3. Детект латинских аватаров

Латинские буквы, визуально совпадающие с кириллическими, заменяются на кириллические аналоги:

| Латинская | Кириллица | Пример |
|-----------|-----------|--------|
| `a` | `а` | `GOST` → не заменяется (нет контекста) |
| `c` | `с` | `norms` → не заменяется |
| `e` | `е` | `GOST` → не заменяется |
| `p` | `р` | `GOST` → не заменяется |
| `o` | `о` | `GOST` → `GOСТ` |
| `x` | `х` | `GOST` → не заменяется |
| `y` | `у` | `GOST` → не заменяется |
| `t` | `т` | не заменяется |

> **Правило**: замена применяется только при наличии смешанных скриптов (латиница + кириллица в одном токене). Если токен содержит только латиницу — он помечается как `needs_review`.

### 3.4. Обработка римских цифр

Римские цифры преобразуются в арабские:

| Римская | Арабская |
|---------|----------|
| I | 1 |
| II | 2 |
| III | 3 |
| IV | 4 |
| V | 5 |
| X | 10 |
| L | 50 |
| C | 100 |
| D | 500 |
| M | 1000 |

**Пример:** `"Глава IV"` → `"глава 4"`

### 3.5. Упрощённая нормализация для иностранных документов

Для `source_type = ISO, IEC, DNV, ABS, ASTM, DIN, EN`:
- Удаление всех разделителей (пробелы, дефисы, точки, двоеточия, скобки, запятые)
- Приведение к нижнему регистру
- Без детекта аватаров и римских цифр

## 4. Извлечение кодов классификации

### 4.1. Регулярные выражения

Парсер анализирует первые 3–5 страниц документа для извлечения кодов:

| Код | Паттерн | Пример |
|-----|---------|--------|
| **МКС/ОКС** | `(?:МКС\|ОКС\|ICS)\s*[:\s]*?(\d{2}(?:\.\d{3}(?:\.\d{2})?)?(?:-\d{2})?)` | `МКС 47.020.30` |
| **ОКСТУ** | `(?:ОКСТУ\|ОК\.СТУ)\s*[:\s]*?(\d{2}(?:\.\d{2}){1,2})` | `ОКСТУ 05.010` |
| **УДК** | `(?:УДК\|UDC)\s*[:\s]*?([\d.:]+)` | `УДК 629.5.021` |
| **Год** | `(?:год\|издан\|утв\.?\|принят).*?(\d{4})` | `утв. 1981` |

### 4.2. Определение эры по году

| Год | Эра |
|-----|-----|
| < 1992 | `USSR` |
| 1992–1999 | `CIS` |
| ≥ 2000 | `RF` |
| Не определён | `CURRENT` |

### 4.3. Формирование classification_status

```json
{
  "mks_status": "CONFIRMED",
  "okstu_status": "NOT_FOUND",
  "udk_code": "629.5.021",
  "extracted_at": "2026-06-13T10:00:00Z",
  "extracted_by": "converter_validator_v3",
  "confidence": 0.89
}
```

**Возможные статусы:**
| Статус | Значение |
|--------|----------|
| `CONFIRMED` | Код найден в справочнике и верифицирован |
| `PENDING_REVIEW` | Извлечён автоматически, требует подтверждения |
| `NOT_FOUND` | Парсер не обнаружил код на первых страницах |
| `NOT_USED` | Не применяется для данной эры/типа документа |
| `UNASSIGNED` | Классификация не назначалась |

## 5. Связь с таблицами БД

| Таблица | Поле | Роль в нормализаторе |
|---------|------|---------------------|
| `registry.documents` | `title_hash_sha256` | Результат вычисления бизнес-ключа |
| `registry.documents` | `title` | Исходное название (не изменяется) |
| `registry.documents` | `normalized_title` | Очищенное название (результат нормализации) |
| `registry.documents` | `classification_status` | JSONB-статусы извлечения кодов |
| `registry.documents` | `era` | Определяется по году из текста |
| `registry.terminology` | `raw_term`, `normalized_value` | Справочник для замены терминов |
| `registry.classifier_registry` | `code`, `full_name` | Валидация извлечённых кодов |

## 6. Примеры работы

### Пример 1: ГОСТ СССР

**Вход:** `"ГОСТ 20868-81 Стойки фундаментные для судовых механизмов"`

**Шаги:**
1. `source_type = gost`, `doc_code = 20868-81`
2. Из текста извлечено: `mks = 47.020`, `year = 1981` → `era = USSR`
3. Токены: `[гост, 20868-81, стойки, фундаментные, для, судовых, механизмов]`
4. `гост` → найдено в terminology → `normalized = гост`
5. Сборка: `гост20868-81стойкифундаментныедлясудовыхмеханизмов`
6. Бизнес-ключ: `SHA-256(USSR|gost|47.020||20868-81|гост20868-81...)`

### Пример 2: Иностранный документ с латинским аватаром

**Вход:** `"DNV Rules For Classification Of Ships"`

**Шаги:**
1. `source_type = dnv`, `is_foreign = true`
2. Упрощённая нормализация: `dnvrulesforclassificationofships`
3. Бизнес-ключ: `SHA-256(CURRENT|dnv|47.020||dnv-ru-ship-pt3|dnvrules...)`

### Пример 3: Смешанный скрипт (опечатка в названии)

**Вход:** `"GOST R 2.105-95 EКСД"` (`C` латинская вместо кириллической `С`)

**Шаги:**
1. `is_foreign = false`, токенизация
2. `GOST` → `гос` (found in terminology)
3. `R` → `р` (found in terminology)
4. `EКСД` → смешанный скрипт: `Е` (кир.) + `К` (кир.) + `С` (лат.) + `Д` (кир.)
   - `С` → `с` (аватар)
   - Результат: `ексд`
5. Сборка: `гостр2.105-95ексд`
6. `needs_review = true` (был аватар)

## 7. Обработка спорных случаев

| Ситуация | Действие | Статус классификации |
|----------|----------|---------------------|
| Код найден в тексте и в справочнике | `CONFIRMED` | `mks_status: CONFIRMED` |
| Код найден в тексте, но не в справочнике | Запись в `classifier_pending` | `mks_status: PENDING_REVIEW` |
| Код не найден на первых страницах | `NOT_FOUND` | `mks_status: NOT_FOUND` |
| Документ иностранный (DNV, ISO) | `NOT_USED` | `okstu_status: NOT_USED` |
| Документ без классификации | `UNASSIGNED` | `mks_status: UNASSIGNED` |
| Обнаружен латинский аватар | `needs_review = true` | Не влияет на статус |
| Год не определён | `era = CURRENT` | — |
