# CAS (Content-Addressable Storage) — спецификация хранения файлов

> Как и почему файлы документов хранятся по хэшу содержимого, а не по имени.

---

## 1. Понятие CAS

**Content-Addressable Storage** — подход, при котором адрес (путь) файла определяется его содержимым, а не произвольным именем. Вместо `documents/gost_20868.pdf` используется путь, содержащий SHA-256 хэш файла.

**Зачем:**
- **Дедупликация**: один и тот же файл (например, один PDF, загруженный дважды) физически хранится один раз
- **Целостность**: имя файла гарантированно соответствует содержимому — изменение содержимого меняет адрес
- **Идемпотентность**: повторная загрузка того же файла не создаёт дубликат, а возвращает ссылку на существующий
- **Защита от коллизий**: разные версии документа не пересекаются в хранилище

---

## 2. Структура пути

```
{doc_id}/v{version_number}/{file_hash_sha256}
```

Где:
- `{doc_id}` — идентификатор документа в `registry.documents` (bigint)
- `v{version_number}` — номер версии файла (начинается с 1)
- `{file_hash_sha256}` — полный SHA-256 хэш бинарного содержимого файла (64 символа, hex)

**Пример:**
```
42/v1/e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
42/v2/a7ffc6f8bf1ed76651c14756a061d662f580ff4de43b49fa82d80a4b80f8434a
```

---

## 3. Опциональное прикрепление оригинального имени

Для удобства отладки и визуальной идентификации к пути может быть добавлен префикс из первых 12 символов хэша и очищенное оригинальное имя файла:

```
{doc_id}/v{version_number}/{hash_prefix}_{safe_filename}
```

Где:
- `{hash_prefix}` — первые 12 символов SHA-256 хэша. Обеспечивает уникальность и связь с хэшем
- `{safe_filename}` — оригинальное имя файла, очищенное от небезопасных символов

**Правила очистки (`safe_filename`):**
- Допустимые символы: буквы (A-Z, a-z, А-Я, а-я), цифры (0-9), точка (`.`), дефис (`-`), подчёркивание (`_`), скобки (`()`, `[]`)
- Пробелы заменяются на `_`
- Все прочие символы удаляются
- Регистр сохраняется

**Пример:**
```
42/v1/e3b0c44298fc_GOST_20868-81_Scan.pdf
42/v2/a7ffc6f8bf1e_GOST_20868-81_Digital.docx
```

> **Важно**: `safe_filename` — исключительно для удобства человека. Единственным гарантом уникальности и целостности является `file_hash_sha256`. Система никогда не должна полагаться на `safe_filename` для идентификации файла.

---

## 4. Вычисление хэша

```
file_hash_sha256 = SHA-256(бинарное содержимое файла)
```

- Хэш вычисляется **до** загрузки файла в MinIO
- Используется криптографическая функция SHA-256 (FIPS 180-4)
- Результат — 64-символьная hex-строка (256 бит)
- Для超大 файлов (например, TIFF-сканов >500 МБ) хэш вычисляется чанками через `hashlib.sha256().update(chunk)`

---

## 5. Гарантия уникальности

На уровне базы данных уникальность обеспечивается **UNIQUE-ограничением** на поле `file_hash_sha256` в таблице `registry.document_versions`:

```sql
CREATE TABLE registry.document_versions (
    id bigint PK,
    document_id bigint FK NOT NULL,
    file_hash_sha256 text UNIQUE,  -- ← гарантирует CAS-дедупликацию
    ...
);
```

**Следствие**: попытка загрузить файл, хэш которого уже есть в БД, приведёт к ошибке `unique_violation`. Обработчик загрузки должен перехватывать это исключение и возвращать ссылку на существующую версию.

## 6. Жизненный цикл файла в CAS

```
                   ┌──────────────────────────────────┐
                   │  Пользователь загружает файл      │
                   └──────────────┬───────────────────┘
                                  ▼
                   ┌──────────────────────────────────┐
                   │  1. Вычисление SHA-256 хэша       │
                   └──────────────┬───────────────────┘
                                  ▼
                   ┌──────────────────────────────────┐
                   │  2. Проверка UNIQUE в БД          │
                   │  ┌─────────┐   ┌──────────────┐  │
                   │  │ Хэш есть │   │ Хэша нет     │  │
                   │  └────┬────┘   └──────┬───────┘  │
                   │       ▼               ▼          │
                   │  Вернуть ссылку    Создать запись │
                   │  на существующую   в document_    │
                   │  версию           versions       │
                   └──────────────────────────────────┘
                                  ▼
                   ┌──────────────────────────────────┐
                   │  3. Формирование CAS-пути         │
                   │  {doc_id}/v{n}/{hash}            │
                   └──────────────┬───────────────────┘
                                  ▼
                   ┌──────────────────────────────────┐
                   │  4. Загрузка в MinIO по CAS-пути  │
                   └──────────────┬───────────────────┘
                                  ▼
                   ┌──────────────────────────────────┐
                   │  5. Обновление file_path в БД     │
                   └──────────────────────────────────┘
```

## 7. Обработка ошибок

| Ситуация | Действие |
|----------|----------|
| `unique_violation` при вставке | Найти существующую запись по хэшу, вернуть её `id` и `file_path` |
| Ошибка MinIO при загрузке | Откатить транзакцию БД (удалить запись `document_versions`) |
| SHA-256 не совпал после загрузки | Удалить файл из MinIO, загрузить заново, обновить хэш |
| Файл повреждён (не открывается парсером) | Пометить версию как `corrupted` в `metadata`, создать новую версию |

---

## 8. Связь с другими компонентами

| Компонент | Как использует CAS |
|-----------|-------------------|
| **Orchestrator** | Вычисляет хэш при загрузке, формирует CAS-путь, сохраняет в MinIO |
| **Registry Service** | Хранит `file_hash_sha256` в `registry.document_versions`, обеспечивает UNIQUE |
| **OCR / Parser** | Получает `file_key` (CAS-путь), читает файл из MinIO по этому пути |
| **Converter-validator** | Читает `file_hash_sha256` из метаданных документа |
| **RAG Builder** | Использует `file_key` для доступа к исходным файлам (изображения, таблицы) |

---

## 9. Отличие от именных путей

| Характеристика | Именной путь (`gost.pdf`) | CAS-путь (`{hash}`) |
|---------------|--------------------------|---------------------|
| Уникальность | Не гарантирована | Гарантирована содержимым |
| Дедупликация | Нет | Да (через UNIQUE) |
| Целостность | Не проверяется | Проверяется (хэш в пути) |
| Человекочитаемость | Высокая | Низкая (без `safe_filename`) |
| Идемпотентность загрузки | Нет (каждый раз новый файл) | Да |
| Контроль версий | По имени | По хэшу |
