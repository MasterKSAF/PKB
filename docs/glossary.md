# Глоссарий терминов и сокращений

## Классификаторы и коды

| Сокращение | Полное название | Описание |
|------------|----------------|----------|
| **МКС** | Межгосударственный классификатор стандартов (ICS — International Classification for Standards) | Иерархический классификатор для каталогизации стандартов. Трёхуровневая структура: раздел (`47`), группа (`47.020`), подгруппа (`47.020.30`). Код вида `31.240` (Электроника. Монтажные изделия). Источник: ОК 001-2021 (ИСО МКС). |
| **ОКС** | Общероссийский классификатор стандартов | Российский аналог МКС. Используется для документов РФ (`era=RF`). В контексте БД синоним МКС. |
| **ОКСТУ** | Общесоюзный классификатор стандартов и технических условий | Классификатор стандартов СССР. Используется для документов советской эпохи (`era=USSR`). Код вида `05.010`. |
| **УДК** | Универсальная десятичная классификация (UDC — Universal Decimal Classification) | Международная система классификации документов. Код вида `621.3` или `669.1` |
| **Национальное расширение МКС** | Дополнительный код через дефис после подгруппы | Для учёта особенностей экономики РФ. Формат: `XX.XXX.XX-XX`, например `27.010-01` (Энергосбережение). Валидируется общим regex-шаблоном МКС. |

## Технические термины

| Термин | Описание |
|--------|----------|
| **RAG** | Retrieval-Augmented Generation — подход к генерации ответов с использованием поиска релевантных фрагментов документов |
| **Секция (section)** | Логический фрагмент документа (раздел, параграф, таблица, рисунок, формула). Назначается Registry при сохранении карточки документа. Хранится в `registry.document_sections` |
| **Chunk (чанк)** | Единица поискового индекса (не более 512 токенов). Получается разбиением секции (одна секция типа `text` → несколько чанков; таблица/изображение/формула → один чанк). Хранится в `rag.document_chunks` |
| **Embedding (эмбеддинг)** | Векторное представление текста (массив чисел с плавающей точкой) для семантического поиска |
| **pgvector** | Расширение PostgreSQL для работы с векторными данными и косинусной близостью |
| **Longpoll** | Механизм асинхронного ожидания: клиент отправляет запрос и держит соединение открытым до получения ответа или истечения таймаута |
| **FSM** | Finite State Machine — конечный автомат, модель смены состояний документа |
| **Saga** | Паттерн распределённых транзакций: последовательность локальных транзакций с компенсационными действиями при сбоях |
| **SHA-256** | Криптографическая хэш-функция, используется для вычисления `file_hash_sha256` (контроль целостности файла) и `title_hash_sha256` (бизнес-ключ документа) |
| **MinIO** | S3-совместимое объектное хранилище для файлов документов |
| **CAS-путь** | Content-Addressable Storage — путь к файлу, определяемый хэшем содержимого, а не именем. Формат: `{doc_id}/v{version_number}/{file_hash_sha256}`. Опционально с префиксом и оригинальным именем: `{hash_prefix}_{safe_filename}`. Детально: `specifications/cas_storage_specification.md`. |
| **JWT** | JSON Web Token — формат токена для аутентификации |
| **RBAC** | Role-Based Access Control — управление доступом на основе ролей |
| **Circuit Breaker** | Паттерн защиты: при N последовательных ошибках вызов этапа блокируется на заданное время |
| **OCR** | Optical Character Recognition — оптическое распознавание текста |
| **Бизнес-ключ (title_hash_sha256)** | SHA-256 от `era \| source_type \| mks_oks_code \| okstu_code \| doc_code \| normalized_title`. Гарантирует уникальность логического документа независимо от количества и формата файлов. Детальный алгоритм нормализации: `specifications/normalizer_specification.md`. |
| **LLM** | Large Language Model — большая языковая модель (используется для генерации ответов) |
| **Bbox** | Bounding box — координаты блока на странице. В `raw_ocr_v4` — сырые пиксели (px) + размер страницы (`page.width`, `page.height`). В `validated_v3` — нормализованные единицы [0,1] (нормирование — ответственность Converter-Validator) |
| **source_type** | Тип нормативного документа-источника (`GOST`, `GOST_R`, `OST`, `RD`, `TU`, `ISO`, `DNV`, `ASTM`, `OTHER`). Указывается в карточке документа. Не путать с `document_type` — категорией контента для поиска |
| **document_type** | Категория контента для фильтрации поиска (`normative`, `technical`, `drawing`, `specification`, `archival_scan`). Определяется классификатором, не зависит от `source_type`. Не путать с `source_type` — типом нормативного документа |
| **sort_by** / **order** | Параметры сортировки для list-эндпоинтов. `sort_by` — поле (`title`, `doc_code`, `created_at`, `updated_at`, `status`, `source_type`); `order` — направление (`asc`, `desc`) |
| **top_k** | Максимальное количество результатов поиска. Диапазон: [1, 100]. По умолчанию: 10 |
| **Черновик (draft)** | Промежуточный результат распознавания документа. Хранится в таблице `registry.drafts` (БД Registry). Управление — через Orchestrator. Внешний идентификатор — `draft_id` (назначается Registry). Логически связан с `task_id` через маппинг Orchestrator. При повторной обработке (retry) создаётся новый черновик. Несколько черновиков группируются по бизнес-ключу документа (`document_key`). Если документ уникален и чист — автоматическое завершение черновика с записью в Registry; при аномалиях — решение человека через `PATCH /drafts/{draft_id}/decide`. |
| **Проект (project)** | Судостроительный проект (заказ), к которому привязаны сессии чата. Хранится в таблице `chat.projects` (схема `chat`). Поля: `id`, `code` (уникальный код, например `21900M2`), `name` (название), `status` (`active`/`archived`/`draft`). Сессия чата привязывается к проекту через `project_id` (FK → `chat.projects.id`), может быть `NULL` для общих вопросов. |
| **classifier_system** | Система классификации. ENUM: `MKS` (межгосударственный), `OKSTU` (общесоюзный), `UDC` (универсальная десятичная), `EXTERNAL` (внешние). Для предметных областей ПКБ используются `categories` с поддержкой иерархии (parent_id). |
| **valid_from** | Дата начала действия документа (`registry.documents.valid_from`, `DATE NOT NULL`). Документ **не действует** до этой даты. Используется в фильтре `GET /registry/documents?valid_at=YYYY-MM-DD` (`:docs/api/registry_service_api.md`). |
| **valid_until** | Дата окончания действия документа (`registry.documents.valid_until`, `DATE NOT NULL`). После этой даты документ **не действует**. Для бессрочных документов — равно `dateMax` (см. ниже). |
| **dateMax** | Символическая константа «бессрочный документ». В PostgreSQL реализуется как нативное значение `'infinity'::date` — корректно работает в B-tree индексах и любых сравнениях (`date < 'infinity'::date == true` для любой реальной даты). Альтернатива для совместимости с не-PG-клиентами: `'9999-12-31'` (выбирается одна конвенция глобально). Применяется к полю `valid_until` для бессрочных документов. Семантика: документ действует от `valid_from` до явной отмены. Детально: `specifications/validity_dates_spec.md` (NEW-16). |
| **valid_at** | Параметр фильтра `GET /registry/documents?valid_at=YYYY-MM-DD`. Возвращает документы, у которых `valid_from <= valid_at AND valid_until >= valid_at` (т.е. действующие на указанную дату). Для бессрочных (`valid_until = dateMax`) фильтрация работает автоматически без специальной обработки. |

## Идентификаторы

|--------|----------|
| **task_id** | BIGINT (sequence) — **внутренний (internal)** ID задачи пайплайна в Orchestrator (`pipeline.tasks`). Агрегирует этапы (`task_steps`) с входными/выходными данными сервисов. Используется только для межсервисного взаимодействия и администрирования. Внешние клиенты используют `draft_id`. |

## Статусы документа

### Статусы черновиков (`registry.drafts`)

| Статус | Описание |
|--------|----------|
| `uploaded` | Файл загружен в MinIO, ожидание запуска preview |
| `previewing` | Выполняется preview-фаза (OCR/Parser + Converter-validator) |
| `ready_for_approve` | Preview завершён, ожидание решения пользователя или автозавершение |
| `approved` | Оператор подтвердил, документ создаётся в Registry |
| `discarded` | Черновик отклонён (человеком или автоматом) |

### Статусы документов (`registry.documents`)

| Статус | Пайплайн | Описание |
|--------|----------|----------|
| `created` | 1 | Документ записан в реестр (registry.documents) |
| `pending_index` | 2 | Ожидание индексации |
| `indexing` | 2 | Выполняется индексация |
| `indexed` | 2 | Документ проиндексирован |
| `failed` | 1/2 | Ошибка на одном из этапов |

|-------|------|----------|

## Справочник ПКБ (P10)

Дополнительный справочник `pkb_domains_classifier.csv` (CSV) и `specifications/pkb_domains.md` (MD) — справочник предметных областей ПКБ. Файл `справочник_предметных_областей_ПКБ.md` (имя в CP1251) перекодирован в UTF-8 (P10-1). Связь с классификаторами — через `mks_oks_code` / `udk_code`.
