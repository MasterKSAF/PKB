# UI/UX

Рабочая зона UI/UX-направления проекта `PKB_neuroassistant`.

## Актуальное состояние

Основной интерфейс находится в:

```text
UI-UX/UI Final/frontend
```

Актуальная ветка для разработки и серверного стенда:

```text
develop
```

Локальные адреса:

```text
UI:      http://127.0.0.1:3300
Gateway: http://127.0.0.1:8080/api/v1
```

Старые папки `frontend-v1` и `frontend-v2` удалены из `develop`, чтобы не мешать анализу и сборке. При необходимости их можно восстановить из истории Git.

## Что умеет UI Final

1. Работает в `demo`-режиме на локальных mock-данных и в продуктивном режиме через Gateway.
2. Поддерживает авторизацию через Gateway/Auth, refresh token и восстановление сессии после обновления страницы.
3. Показывает вкладки по роли и backend-полю `available_tabs`.
4. Содержит основные разделы: чат, база знаний, обработка базы знаний, история, QA и администрирование.
5. Встраивает поиск по документам в `База знаний`; отдельная вкладка поиска не является основным пользовательским сценарием.
6. Поддерживает прямую загрузку файлов, очередь обработки, черновики, метаданные, preview, approve/reject/delete.
7. Показывает реестр документов, версии, историю, ошибки, страницы, предпросмотр и действия с документом.
8. В администрировании содержит пользователей, роли, права, audit и Registry-редакторы классификаторов, терминологии и неизвестных кодов.
9. В продуктивном режиме не должен молча подменять ошибки Gateway demo-данными.

## Роли и доступ

В demo-режиме доступ задается локальной картой ролей в `UI Final/frontend/src/utils/access.ts`.

В продуктивном режиме список вкладок приходит из Gateway/Auth через профиль пользователя (`available_tabs`). UI только мапит backend-вкладки на текущую структуру интерфейса.

| Роль | Demo-вкладки по умолчанию |
| --- | --- |
| Пользователь | `chat`, `documents`, `history` |
| Администратор знаний | `chat`, `documents`, `knowledgeProcessing`, `history` |
| Системный администратор | `chat`, `documents`, `knowledgeProcessing`, `history`, `qa`, `admin` |

`QA` у администратора знаний в продуктивном режиме зависит от `available_tabs` и permissions, а не от demo-карты.

## Ветки и Git

Основная ветка проекта:

```text
develop
```

Актуальный UI должен находиться в `develop`. Старые экспериментальные ветки и исторические UI-материалы не считаются источником истины, если нужные изменения уже перенесены в `UI Final`.

## Что не коммитим

- `node_modules`;
- `dist`;
- временные файлы;
- локальные `.env`;
- локальные логи Gateway;
- большие видеофайлы;
- скриншоты и черновики без необходимости.

Видео встреч храним вне GitHub. В репозитории оставляем MEMO и ссылку на запись.
