# Gateway: стоперы и вопросы для backend

Дата: 13.06.2026

Контекст: список был передан backend после сверки UI Final с Gateway/Registry API. На стороне UI уже закрыты локальные проблемы с ложным offline/audit, счетчиком неизвестных кодов и счетчиком терминологии. После backend-merge список нужно перепроверять на свежем Gateway из `develop`.

| # | Тема | Что нужно от backend | Статус для UI |
| --- | --- | --- | --- |
| 1 | Импорт классификаторов | Подтвердить и реализовать рабочий multipart CSV/XLSX import по `/registry/classifiers/import`. | UI может включить полноценный import после стабильного контракта. |
| 2 | Импорт терминологии | Подтвердить и реализовать рабочий multipart CSV/XLSX import по `/registry/terminology/import`. | UI может включить полноценный import после стабильного контракта. |
| 3 | Валидация классификаторов | Выровнять `/registry/classifiers/validate` с документацией: либо принимать `{ classification: {...} }`, либо зафиксировать другой payload. | UI должен отправлять один канонический формат без fallback-угадывания. |
| 4 | Принятие неизвестного кода | В `/registry/classifiers/pending/{id}/accept` принимать `parent_code`, `full_name`, `admin_comment` и возвращать признак `mapped`. | UI сможет корректно показывать результат маппинга. |
| 5 | Отклонение неизвестного кода | В `/registry/classifiers/pending/{id}/reject` сохранять `admin_comment`. | UI сможет показывать историю решения по коду. |
| 6 | Фильтр неизвестных кодов | Подтвердить/починить фильтр `system` в `/registry/classifiers/pending`. | UI сможет фильтровать очередь по системе-источнику. |
| 7 | Поле `scope` в терминологии | Выровнять контракт `scope`: массив строк по документации или строка; на переходный период желательно принимать оба формата. | UI сейчас должен подстраиваться, но нужен финальный формат. |
| 8 | Нормализация терминов | Для неизвестного термина `/registry/terminology/normalize` должен возвращать согласованный `term_type`, например `unknown`. | UI сможет однозначно показывать неизвестный термин. |
| 9 | Health Gateway | Зафиксировать: `/health` публичный или auth-only; если auth-only, нужен документированный lightweight endpoint для проверки доступности. | UI не должен показывать ложный offline при рабочем Gateway. |

## Уже закрыто на стороне UI

- Ложное сообщение `Система офлайн` при рабочем Gateway и успешных admin/audit запросах.
- `Неизвестные коды (0)` при наличии данных от Gateway.
- `Терминология (0)` при наличии данных от Gateway.

## Что перепроверить после backend-merge

- CSV/XLSX import классификаторов и терминологии из UI.
- Валидацию классификатора на документированном payload.
- Accept/reject неизвестного кода с сохранением комментария администратора.
- Create/update терминологии с финальным форматом `scope`.
- Поведение health-check без ложного offline.
