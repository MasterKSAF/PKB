# UI Final

Актуальная объединенная версия интерфейса PKB Neuroassistant.

## Статус

| Параметр | Значение |
| --- | --- |
| Основная ветка | `develop` |
| Рабочее приложение | `frontend/` |
| Локальный UI | `http://127.0.0.1:3300` |
| Локальный Gateway | `http://127.0.0.1:8080/api/v1` |
| Режимы | продуктивный через Gateway и локальный demo-режим |

`UI Final/frontend` является единственным актуальным UI в `develop`. Папки `frontend-v1` и `frontend-v2` удалены из ветки как архивные.

## Что находится в папке

| Путь | Назначение |
| --- | --- |
| `frontend/` | Актуальное React-приложение: Vite, TypeScript, MUI, Zustand, API-слой, demo-данные, Docker/nginx. |
| `docs/first-run-ui-final.md` | Запуск UI без Gateway. |
| `docs/first-run-ui-final-with-gateway.md` | Запуск UI вместе с локальным Gateway. |
| `docs/ui-final-gateway-docs-adaptation-plan-2026-06-19.md` | План адаптации UI к Gateway/Registry. |
| `docs/ui-final-document-admin-integration-plan-2026-06-16.md` | План интеграции документной админки. |
| `docs/registry-editors-development-task-2026-06-13.md` | Задание на Registry-редакторы. |

## Основные экраны

| Экран | Назначение |
| --- | --- |
| `Вход` | Логин/пароль, переключение demo/prod, восстановление продуктивной сессии по сохраненным токенам. |
| `Чат` | Проекты, дерево чатов, отправка вопроса, longpoll ответа, источники, preview, поиск по текущему чату, feedback. |
| `База знаний` | Разделы, документы, поиск по базе/разделу, preview документа и поиск внутри открытого документа. |
| `Обработка базы знаний` | Загрузка файлов, очередь, черновики, реестр документов, журналы обработки. |
| `История` | Фильтры, поиск по диалогам, раскрытие найденной сессии, продолжение чата, экспорт. |
| `QA` | Метрики качества, журнал проверки и сводка оценок ответов. |
| `Администрирование` | Пользователи, роли, права, audit, Registry-редакторы классификаторов, терминологии и неизвестных кодов. |

Отдельная вкладка `Поиск` не является основным пользовательским сценарием: поиск документов встроен в `База знаний`. Компонент `Search.tsx` пока остается в коде как legacy/reserve route.

## Обработка базы знаний

Вкладка разделена на рабочие зоны:

| Зона | Что делает |
| --- | --- |
| `Загрузка` | Выбор одного или нескольких файлов, создание черновиков, очередь обработки, прогресс и текущий этап. |
| `Черновики` | Список черновиков, сверка и правка метаданных, raw JSON, классификация, preview, approve/reject/delete. |
| `Реестр` | Принятые документы, поиск, фильтры, версии, история, ошибки, страницы, preview, скачивание и удаление. |
| `Журналы` | События обработки, статусы, задачи и диагностическая информация. |

Загрузка по URL удалена. Основной сценарий загрузки - прямая файловая загрузка через Gateway.

## База знаний

Вкладка `База знаний` предназначена для пользовательских сценариев:

1. просмотр разделов;
2. переход внутрь раздела;
3. просмотр документов раздела;
4. поиск по всей базе или выбранному разделу;
5. preview документа;
6. поиск внутри открытого документа.

Административные операции с реестром и документами находятся в `Обработка базы знаний` и `Администрирование`.

## Роли и вкладки

В demo-режиме вкладки задаются локально:

| Роль | Вкладки |
| --- | --- |
| Пользователь | Чат, База знаний, История |
| Администратор знаний | Чат, База знаний, Обработка базы знаний, История |
| Системный администратор | Чат, База знаний, Обработка базы знаний, История, QA, Администрирование |

В продуктивном режиме вкладки определяются backend-профилем (`available_tabs`). UI мапит backend-названия так:

| Gateway tab | UI tab |
| --- | --- |
| `chat` | Чат |
| `search`, `knowledge_base` | База знаний |
| `documents`, `registry`, `knowledge_processing` | Обработка базы знаний |
| `history` | История |
| `monitor`, `qa` | QA |
| `admin` | Администрирование |

Для `systemAdmin` UI дополнительно сохраняет видимость `История`, даже если Gateway не вернул `history`.

## Авторизация в продуктивном режиме

1. UI получает токены через `POST /auth/token`.
2. Профиль, роль, permissions и `available_tabs` подтягиваются через `GET /auth/me`.
3. Access token хранится вместе с refresh token.
4. После reload UI восстанавливает сессию, если токены действуют.
5. При `401 Unauthorized` общий HTTP-слой один раз вызывает `POST /auth/refresh`, сохраняет новый access token и повторяет исходный запрос.
6. Если refresh token невалиден или истек, UI очищает локальную сессию и возвращает пользователя на экран входа.
7. Временное переключение prod -> demo -> prod не отзывает продуктивные токены.
8. `VITE_GATEWAY_AUTO_LOGIN=true` допустим только для локальной отладки.

## Интеграция с Gateway

1. API-слой находится в `frontend/src/utils/http.ts`.
2. В продуктивном режиме UI не должен молча показывать demo-данные при ошибке Gateway.
3. Ошибки backend переводятся в пользовательские сообщения через `frontend/src/utils/errors.ts`.
4. Источники чата и истории нормализуются через `frontend/src/utils/citations.ts`.
5. Скачивание/открытие файлов и preview учитывает внутренние ссылки Gateway/MinIO через `frontend/src/utils/downloadPreview.ts`.
6. Открытые backend-блокеры ведутся отдельно рядом с frontend.

## Быстрый запуск

```powershell
cd "UI-UX/UI Final/frontend"
npm ci
npm run dev -- --host 127.0.0.1 --port 3300 --strictPort
```

Открыть:

```text
http://127.0.0.1:3300
```

Docker-запуск:

```powershell
cd "UI-UX/UI Final/frontend"
docker compose up --build
```
