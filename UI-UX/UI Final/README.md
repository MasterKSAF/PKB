# UI Final

Актуальная объединенная версия интерфейса PKB Neuroassistant.

## Актуальный статус

| Параметр | Значение |
| --- | --- |
| Основная ветка | `develop` |
| Рабочий frontend | `frontend/` |
| Локальный порт UI | `3300` |
| Локальный URL UI | `http://127.0.0.1:3300` |
| Локальный Gateway URL | `http://127.0.0.1:8080/api/v1` |
| Режимы | продуктивный через Gateway и demo-режим |

UI Final сейчас является основной рабочей версией интерфейса. Старые `frontend-v1` и `frontend-v2` в `UI-UX` не являются источником истины.

## Основные экраны

| Экран | Текущее назначение |
| --- | --- |
| `Вход` | Логин и пароль, выбор продуктивного или demo-режима; роль и права в продуктивном режиме подтягиваются через профиль пользователя. Сессия восстанавливается после обновления страницы по сохраненным токенам. |
| `Чат` | Проекты и дерево чатов, отправка вопроса, longpoll ответа, источники, preview, поиск по текущему чату, feedback. |
| `База знаний` | Разделы базы знаний, провал в раздел, список документов, поиск по базе/разделу, предпросмотр документа. |
| `Обработка базы знаний` | Вложенные зоны: загрузка, черновики, реестр документов, журналы обработки. |
| `История` | Поиск по диалогам, фильтры, раскрытие найденного диалога, продолжение чата, экспорт. |
| `QA` | Метрики качества, журнал проверки, оценка ответов ассистента. |
| `Администрирование` | Пользователи, роли, права, audit, редакторы классификаторов, терминологии и неизвестных кодов. |

## Обработка базы знаний

Вкладка разделена на рабочие зоны:

1. `Загрузка`: выбор одного или нескольких файлов и создание черновиков.
2. `Черновики`: компактный список черновиков, metadata review, raw JSON, классификация, preview, approve/reject/delete.
3. `Реестр`: список принятых документов, поиск, предпросмотр, срок действия, меню действий.
4. `Журналы`: очередь и журнал обработки в плотном табличном виде.

Загрузка по URL удалена. Основной сценарий загрузки — прямая файловая загрузка через Gateway.

## База знаний

Вкладка `База знаний` не содержит административных действий. В ней остаются пользовательские сценарии:

1. просмотр разделов базы знаний;
2. переход внутрь раздела;
3. просмотр документов раздела;
4. поиск по всей базе или по выбранному разделу;
5. предпросмотр документа и поиск внутри открытого документа.

## Администрирование и Registry

В UI добавлены редакторы:

1. классификаторы;
2. терминология;
3. неизвестные коды.

Эти разделы работают через Gateway/Registry API в текущем объеме. Если Gateway возвращает ошибку или неполный контракт, UI должен показывать controlled error/empty state, а не молча подменять данные demo-режимом.

## Авторизация в продуктивном режиме

1. UI получает токены через `POST /auth/token`.
2. Профиль, роль и права подтягиваются через `GET /auth/me`.
3. Access token хранится в браузере вместе с refresh token.
4. При обновлении страницы UI сначала проверяет сохраненную сессию и не требует повторного ввода логина/пароля, если токены еще действуют.
5. При `401 Unauthorized` UI один раз вызывает `POST /auth/refresh`, сохраняет новый access token и повторяет исходный запрос.
6. Если refresh token невалиден или истек, UI очищает локальную сессию и возвращает пользователя на экран входа.
7. В продуктивном режиме `VITE_GATEWAY_AUTO_LOGIN` должен оставаться `false`; автоматический вход используется только для локальной отладки.

## Текущее состояние интеграции

1. UI работает с Gateway-first API-слоем в `frontend/src/utils/http.ts`.
2. Чат, история, база знаний, обработка базы знаний, QA, администрирование и Registry-редакторы подключены к текущим Gateway-контрактам.
3. В продуктивном режиме UI не должен молча показывать demo-данные при ошибке Gateway.
4. Авторизация поддерживает refresh token и восстановление сессии после reload страницы.
5. Поиск по базе знаний находится во вкладке `База знаний`; отдельная вкладка `Поиск` не является основным пользовательским сценарием.
6. Сценарий `Проверка` исключен из текущего UI Final как отдельная вкладка, пока нет согласованного API-контракта.
7. Рабочие списки backend-блокеров и последних UI-правок ведутся отдельно и публикуются после согласования.
