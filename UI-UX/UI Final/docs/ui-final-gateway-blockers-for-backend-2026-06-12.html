Блокеры и вопросы к backend

# Область Что меняется Почему это важно Что нужно от backend
1 Схема разделов group остается текущим полем связи, но в следующей версии Gateway его заменят categories с множественными связями. UI уже использует group для текущего контракта; при переходе на categories потребуется безопасная миграция фильтров и навигации. Подтвердить схему categories, формат множественных связей и период совместимости с group.

Что уже закрыто относительно предыдущей версии blockers

  1. Feedback в чате приведен к рабочему формату: UI отправляет числовой rating и rating_status.
  2. GET /chat/history/export работает как файловый/CSV stream; UI скачивает ответ Gateway.
  3. Канонические пути auth/admin используются как /auth/me и /admin/*.
  4. GET /drafts работает без обязательного document_key; UI может получать список черновиков.
  5. Дерево классификаторов доступно через /registry/classifiers/tree.
  6. group, mks_oks_code, okstu_code учитываются в UI для связи документов с разделами.
  7. /tasks/* доступен для админского отображения.
  8. Upload-by-url убран из UI; текущий сценарий загрузки теперь только через прямой выбор файла.

Временное поведение UI до ответов backend

  1. После approve/reject черновика UI нормализует document_id, promoted_document_id, approved_document_id.
  2. Сессии без project_id показываются в fallback-группе Рабочие диалоги только как временная совместимость для старых данных.
  3. Pipeline-разделы можно оставлять как admin-only display, пока backend не попросит отдельный публичный экран артефактов.
