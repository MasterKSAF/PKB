# План модификации: переход на bigint + нормированный bbox

> **Составлен**: 04.06.2026  
> **Причина**: решение архитектора — `document_id` и `version_id` генерируются через БД (sequence) → bigint; bbox окончательно нормированный (0..1).  
> **Дедлайн**: 10.06.2026 (к концу Спринта 1), т.к. это блокирующее изменение для всех сервисов.

---

## 1. Что меняется

| Параметр | Было | Стало | Обоснование |
|----------|------|-------|-------------|
| `task_id` | UUID (в глоссарии), bigint (в плане и некоторых API) | **bigint** (sequence) | Уже был bigint в плане, фиксируем |
| `session_id` | UUID | **bigint** (sequence) | Единообразие, производительность |
| `message_id` | UUID | **bigint** (sequence) | Единообразие, производительность |
| `document_id` | UUID | **bigint** (sequence) | Генерация через БД |
| `version_id` | UUID | **bigint** (sequence) | Генерация через БД |
| `section_id` | BIGINT | **bigint** (sequence) | Без изменений ✅ |
| `chunk_id` | BIGINT | **bigint** (sequence) | Без изменений ✅ |
| `bbox` в `raw_ocr_v4` | Пиксели (10.0, 100.0 и т.д.) | **Нормированный 0..1** | Единый стандарт |
| `bbox` в `validated_v3` | Нормированный 0..1 | Без изменений ✅ | — |

### Идентификаторы, которые остаются без изменений

| ID | Тип | Причина |
|----|-----|---------|
| `file_key` | string (хеш/GUID) | Не ID записи, а путь в MinIO |
| `comparison_id` | ❓ требуется определить | Не используется в текущем API |
| `batch_id` | ❓ требуется определить | Не используется в текущем API |
| `export_id` | UUID / string | Генерируется на лету, не хранится в БД |
| `feedback_id` | bigint (sequence) | Уже числовой в API QueryService |

| Поле | Текущее значение | Новое значение |
|------|-----------------|----------------|
| `task_id` | `"task-a1b2c3-4d5e-6f7a-8b9c-0d1e2f3a4b5c"` | `420000` |
| Все `bbox` | Пиксели (10.0, 100.0, 210.0, 297.0…) | Нормированные 0..1: `[0.048, 0.034, 0.476, 0.061]` и т.д. |
| `pages[].width` | `210` | Оставить (метаданные страницы в мм) |
| `pages[].height` | `297` | Оставить (метаданные страницы в мм) |

**Формула пересчёта bbox:**
```
norm_x = pixel_x / page_width
norm_y = pixel_y / page_height
```

Пример: `bbox: [10.0, 10.0, 100.0, 18.0]` при странице 210×297 →
`bbox: [0.048, 0.034, 0.476, 0.061]`

## 3. Что нужно подготовить для других людей и команд

### 3.1. Разработчикам всех сервисов (общее собрание, среда 04.06)

| # | Что донести | Кому |
|---|------------|------|
| 1 | **Все ID теперь bigint**. Никаких UUID в API-контрактах. | Всем разработчикам |
| 2 | `document_id` и `version_id` генерируются **только через sequence в БД** (Registry). Другие сервисы не генерируют эти ID. | Всем |
